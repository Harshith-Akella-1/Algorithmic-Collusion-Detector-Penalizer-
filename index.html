Architecture · deep-dive

The 1D-CNN classifier

Two convolutional blocks over a 200-event sliding window. Each event carries six channels: normalised timestamp, signed side, log-quantity, agent identity, and one-hot order type (limit / market / cancel). Adaptive max-pool flattens the temporal axis, two dense layers produce class logits.

L01Input events × channels[200, 6]
L02Conv1d kernel 5, pad 2[200, 32]
L03BatchNorm + ReLU[200, 32]
L04MaxPool ÷2[100, 32]
L05Dropout p=0.2[100, 32]
L06Conv1d kernel 5, pad 2[100, 64]

L08AdaptiveMaxPool[1, 64]
L09Linear → ReLU[64]
L10Dropout p=0.3 → Linear[5]

The dataset

5,000 simulated episodes of 600 seconds each, evenly distributed across one clean class and four collusion archetypes. Window-level labelling: a 60-second window is positive only if the labelled scheme period covers ≥ 25% of it.

Class balance is even at the episode level. Within colluding episodes, only the windows overlapping the scheme are labelled positive — so the same episode contributes both positive and negative training samples. Splits are episode-level: no window from a given episode appears in more than one of train / val / test.

The C++ engine

A direct port of the Python reference simulator into C++14, used for fast batch generation. The price-time-priority matching engine, the noise-trader and market-maker logic, and the four colluder schemes are all reimplemented in a single binary.

Parity

Output is statistically compatible with the Python reference but not bit-exact, because Python uses PCG64 and C++ uses Mersenne Twister. Episodes are written as CSV that downstream feature extraction consumes without modification. The Python simulator remains the reference; the C++ engine is the workhorse.
